암호 연산 시각화

키·데이터를 넣으면 DES / 3DES / SEED / AES / RSA가 내부에서 어떻게 돌아가는지 단계별로 보여줍니다. 모든 계산은 브라우저 안에서만 수행됩니다.

    Retail MAC (ISO 9797-1 MAC 알고리즘 3)

    16바이트 키를 K(왼쪽 8B)와 K′(오른쪽 8B)로 나눕니다. 모든 블록은 단일 DES(K)로 CBC 체인을 돌리고, 마지막에만 D(K′) → E(K)를 추가로 해서 결과를 3DES 강도로 만듭니다. IC카드 Secure Messaging, 금융 거래 MAC(EMV 등)에서 가장 흔한 MAC입니다.
    P1→E K→ ⊕P2 →E K→ … → ⊕Pn →E K→D K′→E K→MAC

    RSA

    공개키 암호. 큰 수 N(Modulus)에 대한 거듭제곱 나머지 연산 결과 = 입력^지수 mod N 하나로 암호화·복호화·서명·검증을 모두 합니다.

    키 구성요소 (hex, 직접 입력 가능)

    연산

    EMV 오프라인 데이터 인증 (ODA)

    단말이 카드를 오프라인으로 검증하는 과정입니다. 단말은 브랜드(Visa 등)의 CA 공개키(CAPK)만 갖고 있습니다. 이것으로 카드가 준 Issuer 공개키 인증서를 풀어 Issuer 공개키를 얻고, 그 키로 ICC 공개키 인증서를 풀어 카드 공개키를 얻습니다. 마지막으로 카드가 방금 만든 서명을 검증합니다. 신뢰가 CA → Issuer → 카드로 이어지는 체인입니다.

    데모 카드는 이 페이지에서 만든 가짜 CA 키로 서명한 것이라 실제 Visa CAPK와 무관합니다. 실제 카드에서 읽은 태그 값과 브랜드 CAPK를 아래에 붙여넣으면 같은 검증을 그대로 수행합니다. 값을 한 바이트만 바꿔도 어느 검증이 깨지는지 볼 수 있습니다.

    오프라인 암호화 PIN (CVM: Enciphered PIN verified by ICC)

    단말이 입력받은 PIN을 카드의 🔵 공개키로 암호화해서 카드로 보내면, 카드가 칩 안의 🔴 개인키로 복호화해 PIN을 확인합니다. 단말과 카드 사이를 엿들어도 PIN을 알 수 없고, 카드가 매번 새 난수(챌린지)를 넣게 해서 녹음한 암호문을 다시 보내는 공격(재전송)도 막습니다.
    카드 공개키 확보 (인증서 체인)→GET CHALLENGE→PIN 블록 구성→🔵 공개키로 암호화→VERIFY (P2=88)→🔴 카드가 개인키로 복호화→7F · 난수 · PIN 확인→90 00 / 63 Cx

    키 길이를 바꾸거나 카드를 새로 발급하려면 EMV ODA 탭에서 "데모 카드 새로 발급"을 누르세요. 이 탭은 그 데모 카드를 그대로 씁니다.

    EMV 거래 전체 흐름 — 카드를 꽂고 영수증이 나올 때까지

    단말과 카드가 주고받는 명령(APDU)을 순서대로 보여줍니다. 앞 단계들은 문제가 있어도 거래를 바로 끊지 않고 TVR(단말 검증 결과)에 비트만 켭니다. 그런 다음 단말 행동 분석에서 TVR과 TAC/IAC를 비교해 거절·온라인·오프라인 승인 중 하나를 고르고, 최종 결정은 카드가 GENERATE AC로 내립니다. 아래 조건을 바꿔 보면 흐름이 어떻게 갈라지는지 볼 수 있습니다.
    ① 응용 선택→② GPO→③ 레코드 읽기→④ ODA→⑤ 처리 제한→⑥ 본인 확인→⑦ 단말 위험관리→⑧ 단말 행동 분석→⑨ 1st GEN AC→⑩ 온라인 · 발급사 인증→⑪ 2nd GEN AC→⑫ 스크립트

    거래 조건

    TAC / IAC 값 (예시 값 — 브랜드·발급사마다 다름)

    TAC는 단말(브랜드 규칙) 설정, IAC는 카드에 든 발급사 설정입니다. 둘을 OR 해서 TVR과 겹치는지 봅니다. 예: IAC-Denial을 0040000000으로 바꾸고 카드를 "만료됨"으로 하면 오프라인에서 바로 거절됩니다.

    AID·카드 데이터·키는 학습용 예시입니다. ARQC/TC/ARPC/스크립트 MAC은 다른 탭과 같은 함수로 실제 계산하고, 인증서·서명·PIN 암호문은 길이만 맞춘 자리표시 값입니다(실제 계산은 EMV ODA·오프라인 PIN 탭). 카드 위험관리(카드가 요청을 낮추는 판단)와 CVR/IAD 내용은 브랜드 사양마다 달라 단순화했습니다.

    ARQC 계산 — 거래 데이터에 카드가 찍는 도장 (MAC)

    ARQC는 거래 데이터의 MAC입니다. 카드는 발급사 마스터키(IMK)에서 유도된 자기만의 키로 MAC을 계산합니다. 발급사는 같은 키를 다시 유도해 똑같이 계산하고 비교합니다. 같으면 진짜 카드이고, 데이터가 그대로이며, 지금 만든 것이라는 뜻입니다. 거래 데이터 자체는 평문으로 갑니다.
    IMK (발급사 HSM)→ PAN·PSN →ICC 마스터키 (카드에 저장)→ ATC →세션키 (이번 거래만)→ 거래 데이터 + Retail MAC →ARQC 8B→발급사 검증→ARPC

    발급사 키 · 카드 정보

    거래 데이터 (CDOL1 — GENERATE AC에 단말이 넣어주는 값 + 카드 값)

    승인 응답 · 변조 실험

    입력할 데이터 목록과 순서는 EMV Book 2 권장 최소 세트입니다. 실제 카드는 CDOL1과 브랜드·CVN 스펙에 따라 IAD(CVR) 등 카드 데이터를 더 넣습니다. 그런 데이터는 "추가 카드 데이터"에 hex로 넣으세요.

    발급사 스크립트 (Issuer Script) — Secure Messaging

    발급사가 승인 응답에 카드 관리 명령(PIN 변경, 카드 차단 등)을 실어 보냅니다. 명령마다 MAC(MK-SMI 세션키)을 붙이고, 새 PIN 같은 비밀 데이터는 암호화(MK-SMC 세션키)합니다. MAC에 이번 거래의 ATC·ARQC가 들어가므로 이번 거래에서만 통합니다. 카드는 MAC이 맞을 때만 복호화하고 실행합니다.
    1st GENERATE AC → ARQC→발급사: 세션키 유도 (R = ARQC)→데이터 암호화 (SMC)→MAC 계산 (SMI)→71/72 TLV로 응답→카드: MAC 확인 → 복호화 → 실행→9F5B 결과

    발급사 키 · 이번 거래 (ATC·ARQC는 ARQC 탭에서 가져옴)

    세션키는 EMV 공통 세션키 방식(R = ARQC), MAC 입력은 헤더 | ATC | ARQC | 데이터를 기본형으로 썼습니다. MAC 길이, ATC·ARQC 포함 여부, 새 PIN 데이터 구성(카드 키와 XOR 하는지 등), 암호화 모드는 브랜드·CVN 사양마다 달라서 옵션으로 두었습니다.

    EMV TLV 파서

    카드 응답, DE 55 같은 BER-TLV hex를 붙여넣으면 태그·길이·값으로 나누고 의미를 풀어줍니다 (EMV Book 3 Annex B).
    태그
    첫 바이트 하위 5비트가 11111(1F)이면 다음 바이트도 태그이고, 그 바이트의 최상위 비트가 1이면 또 이어짐 (예: 9F 27, BF 0C). 첫 바이트 b6(0x20)이 1이면 constructed = 값 안에 TLV가 또 들어 있음 (6F, 70, 77, A5…).
    길이
    00~7F = 그대로 길이 · 81 xx = 다음 1바이트가 길이 (128~255) · 82 xx xx = 다음 2바이트가 길이
    DOL
    8C·8D·9F38·9F49 같은 DOL은 TLV가 아니라 "태그 + 길이" 목록입니다. 단말은 그 순서대로 값만 이어붙여 보냅니다.

    Visa ARQC 검증 — 9F26·9F10이 있는 데이터를 인식함

    IAD(9F10)에서 CVN을 읽고 그 규칙대로 데이터를 모아 ARQC를 다시 계산합니다. 지원: CVN 10, CVN 18 (IAD 형식 0/1/3).

    PKCS#11 호출 형태 (공통 패턴)

    모든 연산이 Init(메커니즘, 키) → 실행의 두 단계입니다. 출력 길이는 버퍼 없이 한 번 호출해 길이를 받은 뒤 버퍼를 잡고 다시 호출하는 것이 관례입니다.
    CK_BYTE iv[8] = {0};
CK_MECHANISM mech = { CKM_DES3_CBC, iv, sizeof(iv) };   // 메커니즘 + 파라미터(IV)

C_EncryptInit(hSession, &mech, hKey);                  // 1) 어떤 방식·어떤 키로
CK_ULONG outLen = 0;
C_Encrypt(hSession, in, inLen, NULL, &outLen);           // 2) 출력 길이만 조회
out = malloc(outLen);
C_Encrypt(hSession, in, inLen, out, &outLen);            // 3) 실제 실행

// 서명 검증은 출력이 없음: 반환값으로 판단
C_VerifyInit(hSession, &(CK_MECHANISM){CKM_SHA256_RSA_PKCS, NULL, 0}, hPubKey);
rv = C_Verify(hSession, data, dataLen, sig, sigLen);    // CKR_OK 또는 CKR_SIGNATURE_INVALID

// EMV 인증서 복원: 공개키로 Raw RSA
C_VerifyRecoverInit(hSession, &(CK_MECHANISM){CKM_RSA_X_509, NULL, 0}, hCapk);
C_VerifyRecover(hSession, cert90, k, recovered, &recLen); // recovered = 6A 02 ... BC

    긴 데이터는 C_EncryptUpdate / C_SignUpdate로 나눠 넣고 …Final로 마칩니다 (멀티파트). 단, RSA Raw처럼 한 번에만 되는 메커니즘도 있습니다.

    용어 사전

    블록 암호 (Block cipher)
    고정 크기 블록 단위로 암호화합니다. DES/3DES는 8바이트, SEED/AES는 16바이트입니다. 데이터가 블록보다 길면 블록으로 나누고 모드로 연결합니다.
    ECB (Electronic Codebook)
    각 블록을 독립적으로 암호화합니다. 같은 평문 블록은 항상 같은 암호문 블록이 됩니다. IC카드에서는 키 암호화(키 교환)처럼 한 블록짜리 연산에 자주 씁니다.
    CBC (Cipher Block Chaining)
    평문 블록을 직전 암호문 블록(첫 블록은 IV)과 XOR한 뒤 암호화합니다. 앞 블록이 바뀌면 뒤 블록이 전부 바뀝니다. MAC 계산도 CBC가 기반입니다.
    IV (Initial Vector, 초기 벡터)
    CBC 첫 블록에 XOR하는 값. 블록 크기와 같습니다. 카드 스펙에서는 보통 00…00을 씁니다.
    패딩 (Padding)
    데이터 길이를 블록 크기의 배수로 맞추려고 붙이는 바이트입니다.
    • ISO 9797-1 방법1: 00으로 채움 (이미 배수면 안 붙임 → 복호화 후 원래 길이를 알 수 없음)
    • ISO 9797-1 방법2: 80 하나 붙이고 00으로 채움 (항상 붙임). IC카드 Secure Messaging, MAC에서 매우 흔함
    • PKCS#7: 부족한 바이트 수 n을 n개 붙임 (예: 3바이트 부족 → 03 03 03)
    MAC (Message Authentication Code)
    데이터가 위·변조되지 않았고 같은 키를 가진 쪽이 만들었음을 증명하는 짧은 값입니다. 데이터는 암호화하지 않고 뒤에 MAC만 붙입니다. 카드와 단말이 같은 키로 MAC을 각각 계산해 비교합니다.
    Retail MAC (ISO 9797-1 MAC 알고리즘 3, ANSI X9.19)
    16바이트 키 K‖K′. 모든 블록을 단일 DES(K)로 CBC 연결하고, 마지막 결과에만 D(K′) → E(K)를 적용합니다. 블록마다 3DES를 하는 것보다 빠르면서 최종 결과는 3DES 강도입니다. 패딩은 보통 방법2(80 00…)입니다. 스펙에 따라 8바이트 결과 중 앞 4바이트만 쓰기도 합니다.
    ODA (Offline Data Authentication)
    단말이 발급사에 접속하지 않고 RSA 인증서 체인으로 카드가 진짜인지 확인하는 과정 (EMV Book 2).
    • SDA: 발급사가 미리 서명한 정적 데이터(93)만 확인 → 데이터 위·변조는 막지만 복제 카드는 못 막음
    • DDA: 단말 난수(UN)에 카드가 ICC 개인키로 그 자리에서 서명(INTERNAL AUTHENTICATE) → 복제 방지
    • CDA: GENERATE AC 응답의 Application Cryptogram까지 함께 서명 → 거래 결과 위·변조까지 방지
    실패하면 TVR 1바이트의 SDA 실패(b7) / DDA 실패(b4) / CDA 실패(b3) 비트가 켜집니다.
    CAPK (Certification Authority Public Key)
    브랜드(Visa, Mastercard 등)의 최상위 공개키. 단말에 미리 저장돼 있고, RID(AID 앞 5바이트, 예: Visa A000000003)와 카드가 알려주는 CA PK Index (8F)로 고릅니다.
    인증서 복원 (Recovery)
    EMV 인증서는 "서명 = 데이터^d mod N" 형태라서 공개키로 서명^e mod N을 계산하면 원래 데이터가 그대로 나옵니다 (ISO 9796-2 방식, 메시지 복원형 서명). 복원된 데이터는 항상 6A로 시작하고 BC로 끝나며, 안에 다음 단계 공개키와 SHA-1 해시가 들어 있습니다.
    Remainder (92, 9F48)
    인증서 안에는 다음 공개키를 넣을 자리가 (상위 키 길이 − 36 또는 42)바이트밖에 없습니다. 공개키가 더 길면 넘치는 오른쪽 부분을 Remainder 태그로 따로 줍니다. 짧으면 남는 자리를 BB로 채웁니다.
    Static Data to be Authenticated
    AFL에서 "ODA에 포함"으로 지정된 레코드들의 데이터를 이어붙인 것입니다 (SFI 1~10은 태그 70과 길이를 뺀 내용, SFI 11~30은 70 포함 전체). 9F4A(SDA Tag List)에 82가 있으면 AIP 값을 뒤에 붙입니다. ICC 인증서(DDA/CDA)나 93(SDA)의 해시 계산에 들어가므로 PAN, 유효기간 등이 바뀌면 검증이 실패합니다.
    KCV (Key Check Value)
    키를 노출하지 않고 키가 맞는지 확인하는 값. 보통 00…00 블록을 그 키로 암호화한 결과의 앞 3바이트입니다. 키 주입/교환 시 양쪽 KCV를 비교합니다. (AES는 스펙에 따라 01…01을 쓰기도 합니다)
    패리티 비트 (DES 키)
    DES 키 8바이트에서 각 바이트의 마지막 비트(LSB)는 키로 쓰이지 않습니다. 홀수 패리티(바이트의 1 개수가 홀수)를 맞추는 용도라 실제 키는 56비트입니다.
    3DES (TDEA) / 2-Key, 3-Key
    DES를 세 번 적용합니다. 암호화 = EK3(DK2(EK1(P))) (EDE). 16바이트 키(2-Key)는 K1|K2이고 K3=K1입니다. K1=K2=K3이면 단일 DES와 결과가 같습니다(하위 호환).
    Feistel 구조
    블록을 왼쪽 L, 오른쪽 R로 나누고 매 라운드 L' = R, R' = L ⊕ F(R, 라운드키)를 반복합니다. 라운드키 순서만 거꾸로 하면 같은 회로로 복호화됩니다. DES와 SEED가 이 구조입니다.
    라운드 키 / 키 스케줄
    원래 키에서 라운드마다 쓸 키를 뽑아내는 과정입니다. DES는 48비트 키 16개, SEED는 64비트 키 16개, AES는 블록 크기와 같은 키 (라운드 수 + 1)개를 만듭니다.
    S-box (치환 상자)
    입력 값을 표에서 찾아 다른 값으로 바꾸는 비선형 치환표입니다. 암호의 핵심 혼돈(confusion) 요소입니다.
    AES 상태 행렬 (State)
    16바이트 블록을 4×4 행렬에 열 우선으로 배치합니다. 입력 바이트 0,1,2,3이 첫 번째 열이 됩니다. SubBytes→ShiftRows→MixColumns→AddRoundKey를 라운드마다 반복합니다(마지막 라운드는 MixColumns 없음).
    Modulus (N, 모듈러스)
    RSA에서 두 소수의 곱 N = P × Q. "RSA 2048"의 2048은 N의 비트 수입니다. 공개키에도 개인키에도 들어가며, 모든 연산 결과는 0 이상 N 미만입니다. 그래서 입출력 블록 길이는 N의 바이트 길이(k)와 같습니다.
    Public Exponent (e, 공개 지수)
    공개키 연산(암호화, 서명 검증)에 쓰는 지수. 거의 항상 65537(01 00 01) 또는 3입니다. 짧아서 공개키 연산이 빠릅니다.
    Private Exponent (d, 개인 지수)
    개인키 연산(복호화, 서명)에 쓰는 지수. e·d ≡ 1 (mod φ(N))을 만족하고 길이가 N과 비슷합니다.
    CRT (중국인의 나머지 정리) 키: P, Q, DP, DQ, QInv
    개인키 연산을 N 대신 절반 크기인 P, Q로 나눠 계산하면 약 4배 빨라집니다. IC카드는 대부분 CRT 형식으로 개인키를 저장합니다.
    DP = d mod (P−1), DQ = d mod (Q−1), QInv = Q⁻¹ mod P (스펙에 따라 PQ, U, Coefficient라고도 부름)
    계산: m1 = c^DP mod P, m2 = c^DQ mod Q, h = QInv·(m1−m2) mod P, m = m2 + h·Q
    φ(N) (오일러 피 함수)
    (P−1)(Q−1). d를 구할 때 씁니다. N을 소인수분해하지 못하면 φ(N)을 알 수 없고, 그래서 d를 구할 수 없다는 것이 RSA 안전성의 근거입니다.
    PKCS#1 v1.5 패딩
    데이터를 N 길이(k바이트)로 맞추는 형식.
    • 암호화(BT 02): 00 02 [0이 아닌 난수 ≥8바이트] 00 [데이터]
    • 서명(BT 01): 00 01 FF FF … FF 00 [데이터(보통 DigestInfo+해시)]
    맨 앞 00 덕분에 블록 값이 항상 N보다 작습니다.
    DER / ASN.1 (TLV)
    키를 파일로 저장할 때 흔히 쓰는 형식. 모든 항목이 Tag(02=INTEGER, 30=SEQUENCE) + Length + Value로 이어집니다. 길이가 128 이상이면 81 xx 또는 82 xx xx처럼 길이 바이트 수를 먼저 적습니다. INTEGER 최상위 비트가 1이면 음수로 읽히지 않게 00을 앞에 붙입니다. IC카드 APDU의 TLV(BER-TLV)도 같은 원리입니다.
    Square-and-Multiply
    큰 거듭제곱을 빠르게 계산하는 방법. 지수를 2진수로 보고 비트마다 "제곱", 비트가 1이면 "곱하기"를 추가로 합니다. 2048비트 지수도 약 2048번의 제곱으로 끝납니다.
